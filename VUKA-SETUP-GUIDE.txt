STEP 2 — SUPABASE (Database + Auth) — FREE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Supabase gives you a real PostgreSQL database + authentication for free.

1. Go to https://supabase.com and click "Start your project"
2. Sign up with GitHub (easiest)
3. Click "New Project"
   → Name: vuka
   → Database Password: pick a strong one, WRITE IT DOWN
   → Region: pick closest to you (e.g. eu-central-1 for SA users)
   → Click "Create new project" (takes ~2 minutes to spin up)

4. Once it's ready, go to Settings → API
   You'll see:
   → Project URL       → copy this (looks like: https://abcxyz.supabase.co)
   → anon public key   → copy this (long string starting with "eyJ...")

5. Still in Settings → API, scroll down to "Service role key"
   → Click "Reveal" and copy it (keep this secret!)

6. Go to Settings → Database
   → Scroll to "Connection string" → select "URI"
   → Copy the "Transaction" connection string (port 6543)
     Looks like: postgresql://postgres.abcxyz:PASSWORD@aws-0-eu.pooler.supabase.com:6543/postgres
   → Also copy the "Session" connection string (port 5432)

7. Open your vuka folder → open the file called ".env.local"
   Fill in:

   NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...your anon key...
   SUPABASE_SERVICE_ROLE_KEY=eyJ...your service role key...
   DATABASE_URL=postgresql://postgres.XXX:PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres?pgbouncer=true
   DIRECT_URL=postgresql://postgres.XXX:PASSWORD@aws-0-REGION.pooler.supabase.com:5432/postgres

   NOTE: In DATABASE_URL, add ?pgbouncer=true at the end (port 6543)
   NOTE: DIRECT_URL uses port 5432 with no extra params

8. In Supabase dashboard, go to Authentication → Providers
   → Make sure "Email" is enabled (it should be by default)
   → Optional: enable Google OAuth (Settings → Client ID / Secret from Google Cloud Console)

STEP 3 — PUSH THE DATABASE SCHEMA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This creates all the tables in your Supabase database.

In your terminal (inside the vuka folder):

   npm run db:push

You should see "Your database is now in sync with your Prisma schema."

To verify: go to Supabase → Table Editor
You should see tables: User, Artist, Beat, Release, Track, Purchase, etc.

STEP 4 — STRIPE (Payments) — FREE TEST MODE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Go to https://stripe.com → click "Start now" → create a free account
2. Verify your email
3. You're now in TEST MODE (no real money, safe to use)

4. In Stripe dashboard, click "Developers" (top right) → API keys
   → Copy "Publishable key" (starts with pk_test_...)
   → Click "Reveal test key" → copy "Secret key" (starts with sk_test_...)

5. In your .env.local:
   STRIPE_SECRET_KEY=sk_test_...
   NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...

6. Set up the webhook for local testing:
   Open a NEW terminal window (keep the first one open) and run:

   stripe login
   (opens browser, click "Allow access")

   Then:
   stripe listen --forward-to localhost:3000/api/checkout/stripe/webhook

   It will print something like:
   "Your webhook signing secret is whsec_abc123..."
   → Copy that secret

7. In your .env.local:
   STRIPE_WEBHOOK_SECRET=whsec_abc123...

   IMPORTANT: Keep this terminal running while testing payments.
   Every time you run the app locally, re-run the stripe listen command.

STEP 5 — PAYFAST SANDBOX (SA Payments) — FREE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PayFast provides test credentials you can use immediately — no account needed
for sandbox testing.

In your .env.local, these sandbox credentials are already filled in:

   PAYFAST_MERCHANT_ID=10000100
   PAYFAST_MERCHANT_KEY=46f0cd694581a
   PAYFAST_PASSPHRASE=
   PAYFAST_SANDBOX=true

Leave them exactly like that. PayFast sandbox works with these default values.

NOTE: PayFast ITN (their webhook) cannot reach localhost, so to test PayFast
payments end-to-end you need either:
  a) Deploy to Vercel (free) and test there — see Step 9
  b) Use ngrok (free): ngrok http 3000 → gives you a public URL

For NOW, focus on testing Stripe (works perfectly with localhost).
PayFast is just another payment method — the logic is identical.

STEP 6 — CLOUDFLARE R2 (File Storage) — FREE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

R2 is where your audio files live. Free tier = 10GB storage.

1. Go to https://cloudflare.com → sign up (free)
2. In the dashboard, click "R2 Object Storage" in the left menu
3. Click "Create bucket"
   → Name: vuka-audio
   → Location: Automatic
   → Click "Create bucket"

4. Set up public access (for previews/artwork):
   → Click on your bucket → Settings tab
   → Under "Public access" → click "Allow Access"
   → Copy the "Public bucket URL" (looks like: https://pub-XXX.r2.dev)

5. Create API credentials:
   → Go to R2 overview page (not inside the bucket)
   → Click "Manage R2 API Tokens" (top right)
   → Click "Create API token"
   → Name: vuka-local
   → Permissions: "Object Read & Write"
   → Click "Create API Token"
   → Copy the "Access Key ID" and "Secret Access Key"
   → Also note your Account ID (shown on R2 overview page)

6. In your .env.local:
   CLOUDFLARE_R2_ACCOUNT_ID=your-account-id
   CLOUDFLARE_R2_ACCESS_KEY_ID=your-access-key-id
   CLOUDFLARE_R2_SECRET_ACCESS_KEY=your-secret-access-key
   CLOUDFLARE_R2_BUCKET_NAME=vuka-audio
   CLOUDFLARE_R2_PUBLIC_URL=https://pub-XXX.r2.dev

STEP 10 — DEPLOY TO VERCEL (Still Free, Still No Domain)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Vercel gives you a free public URL like https://vuka-app.vercel.app
This lets you:
  - Test PayFast end-to-end (PayFast can't reach localhost)
  - Share with friends/testers
  - Test on mobile
  - Keep it running without your laptop being on

1. Create a free account at https://vercel.com (sign up with GitHub)

2. Push your code to GitHub first:
   a. Go to https://github.com → New repository → name it "vuka-app"
   b. In your terminal (inside vuka folder):
      git init
      git add .
      git commit -m "Initial Vuka build"
      git branch -M main
      git remote add origin https://github.com/YOURUSERNAME/vuka-app.git
      git push -u origin main

3. In Vercel:
   → Click "Add New Project"
   → Import your GitHub repo "vuka-app"
   → Framework: Next.js (auto-detected)
   → Click "Environment Variables"
   → Add ALL the variables from your .env.local (one by one)
   → IMPORTANT: Change NEXT_PUBLIC_APP_URL to your Vercel URL
     e.g. https://vuka-app.vercel.app
   → Click "Deploy"

4. After deploy, go to Stripe dashboard → Developers → Webhooks
   → Click "Add endpoint"
   → URL: https://vuka-app.vercel.app/api/checkout/stripe/webhook
   → Events to listen to: checkout.session.completed
   → Copy the new signing secret → update STRIPE_WEBHOOK_SECRET in Vercel env vars
   → Redeploy (Vercel → your project → Redeploy)

5. Now test PayFast:
   → Go to your Vercel URL
   → Buy a beat using PayFast
   → PayFast will fire the ITN to your live URL
   → Check dashboard for confirmed purchase
   ✅ PayFast end-to-end confirmed

COMMON ERRORS AND FIXES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"Can't connect to database"
  → Check DATABASE_URL in .env.local
  → Make sure you ran: npm run db:push
  → Check Supabase project is not paused (free tier pauses after 1 week idle)
    → Go to supabase.com → click your project → click "Restore"

"Webhook signature verification failed"
  → Make sure stripe listen is running in a separate terminal
  → Make sure STRIPE_WEBHOOK_SECRET matches what stripe listen printed

"Invalid API key" (Stripe)
  → Double-check you copied the full key including "sk_test_" prefix
  → No spaces before or after the key in .env.local

"Upload failed"
  → Check Cloudflare R2 credentials
  → Make sure the bucket name matches exactly: vuka-audio
  → Make sure your R2 token has "Object Read & Write" permission

"Email not sending"
  → Check RESEND_API_KEY is correct
  → Use EMAIL_FROM=onboarding@resend.dev for testing
  → Check Resend dashboard → "Emails" tab to see if it was attempted

"Module not found" errors
  → Run: npm install
  → If that fails: delete the node_modules folder and run npm install again

Prisma errors after schema change
  → Run: npm run db:push
  → If that fails: npm run db:push -- --force-reset (WARNING: clears all data)
